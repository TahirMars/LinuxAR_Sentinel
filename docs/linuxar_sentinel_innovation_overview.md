# LinuxAR Sentinel 创新方案说明

## 1. 项目定位
LinuxAR Sentinel（灵哨）是面向 Linux 主机的 Rootkit 事件响应工具，采用 `run-once` 模式，在一次执行中完成采集、检测、关联分析、证据导出和处置建议输出，降低应急处置门槛。

## 2. 核心模块
项目按能力分为五个模块：
- 模块 A：运行框架与能力探测（内核版本、BTF、eBPF可用性判断）。
- 模块 B：eBPF/系统双通道采集（优先 eBPF，失败自动回退系统快照）。
- 模块 C：隐藏与劫持检测（模块可见性、VFS ownership、syscall/VFS基线漂移）。
- 模块 D：证据管道与报告（`summary/findings/verdict/modules/network/bpf`）。
- 模块 E：增强处置（隔离建议、证据保全、后续联动接口）。

## 3. 结合 AI 的创新点
建议在现有规则引擎之上增加 AI 增强层：
- 告警语义化：将技术异常自动翻译为“风险-影响-建议”三段式描述，减少人工解读时间。
- Rootkit 候选归因：基于符号、路径、hook 行为、网络特征生成候选名称与置信度，而非长期 `unknown`。
- 多证据自动关联：把 `modules/network/bpf/fops` 证据自动归并成攻击链叙事，输出可直接用于汇报的摘要。
- 误报抑制与学习：对历史处置结论做反馈学习，动态调整规则阈值和白名单策略。
- 处置建议生成：按风险等级自动生成分级响应清单（隔离、取证、核验、回滚）。

## 4. 人力节省与效率收益
相对传统人工排查（手工执行 `lsmod/ss/bpftool/kallsyms` 并整理证据）：
- 单机排查耗时可从“小时级”压缩到“分钟级”。
- L1 分析员可直接消费结构化结论，减少对资深内核安全工程师的依赖。
- 报告生成自动化后，值班人员可将更多时间投入复盘和加固，而非数据搬运。

## 5. 业务价值说明
- 降低 MTTR：更快定位内核态隐蔽威胁，减少业务中断窗口。
- 提升一致性：同一套流程和证据格式适用于不同内核版本与主机环境。
- 可审计可复盘：标准化证据目录便于留痕、复核和合规审计。
- 可扩展：后续可接入 SOAR/SIEM，实现自动告警闭环。

## 6. 落地建议与衡量指标
- 先在测试环境上线 AI 增强报告，不直接驱动自动处置。
- 以月度看板跟踪：`告警准确率`、`误报率`、`平均分析时长`、`MTTR`、`单人日处理主机数`。
- 达到阈值后再逐步开放“自动化联动”能力（如隔离、工单、回滚策略）。
